源码和产物现在是分开的两个文件夹
──────────────────────────────────
  桌面\源代码\      ← 改代码在这里
  桌面\Scoop\       ← 出包的结果在这里

  Scoop\ 里面有什么：
    Scoop Words-电脑版.html   双击即用，断网也能用
    Scoop Words-手机版.html   内容完全相同，拷到手机上用浏览器打开
    部署包/                   上传到免费托管 → 手机加桌面图标（步骤见 使用说明.txt）
    部署包.zip                同上，传 zip 更省事
    使用说明.txt              给使用者看的说明
    Scoop\源代码\             打包时自动复制的**快照**，别在那里改！
    重新构建说明.txt          本文件

★ 日常使用根本不需要源码，双击 HTML 就行了。

⚠ Scoop\源代码\ 是快照，不是真的源码。
  每次打包都会整份覆盖，在那儿改的东西会丢。
  要改代码去 桌面\源代码\。

产物为什么没撒在桌面上：
  打包脚本默认把产物写在「源代码」的上一级 —— 源码一挪到桌面，
  这就变成往桌面根目录扔 70MB。所以在 源代码\build.config.json 里
  指了一下输出目录：{ "outDir": "../Scoop" }
  改了这个文件记得存成**不带 BOM** 的 UTF-8（记事本和 PowerShell 都会加 BOM）。


改了源代码之后怎么重新出包
──────────────────────────
「源代码/node_modules」和「源代码/dist」已经删掉了，这两样加起来占了 229MB，
而且都是一条命令就能再生的（前者是依赖缓存，后者是构建产物），留着没意义。

所以第一次出包前，先装依赖：

    cd 桌面\源代码
    npm install --ignore-scripts

  ⚠ 必须用 npm install --ignore-scripts，不要用 npm ci。
    依赖里有个 better-sqlite3 需要现场编译，会去找 Python，
    这台机器上能找到的 Python 版本不满足要求，npm ci 会直接报错退出。
    --ignore-scripts 跳过编译；那个包只有生成词库数据的脚本用得到，
    打包 App 完全不需要它。

装完之后：

    npm run build            # 类型检查 + 生成 dist/（部署包的内容）
    npm run build:desktop    # 一条龙：单文件 HTML + 部署包/ + 部署包.zip

build:desktop 会把产物写到「源代码」的上一级目录，也就是本文件夹。
所以这个文件夹整体挪到哪、改成什么名字，都不会出问题。

  💡 想再省点空间：装完依赖后可以删掉 node_modules 里这两个包，
     它们只被两个很少跑的脚本用到，删了照样能打包 App：
       node_modules/better-sqlite3    26MB   只有 build-data.mjs 用（重跑词库数据）
       node_modules/@napi-rs          37MB   只有 make-icons.mjs 用（重画手机图标）
     要用的时候 npm install --ignore-scripts 再装回来即可。

  💡 源码本身只有 28MB，其中 28MB 还是 public/ 里的词库数据
     （9 本词书 + 释义库 + 例句库），这个不能删，删了 App 就没词了。

查词的释义库（dict.json）有个补丁，别丢
──────────────────────────────────────
  · scripts/patch-inflections.mjs   给变形词补条目（had / were / did / went …）

  背景：dict.json 是 build-data.mjs 从 ECDICT 筛出来的，条件是「词频前 5 万 或 带考纲标签」。
  但 had / has / were / did / went 这些变形词在 ECDICT 里**既没有词频排名也没有考纲标签**，
  全被筛掉了 —— 查 "had" 会显示「词库未收录」，而 have / was / go 都好好的。

  补法：ECDICT 给每个词标了 forms（have -> having,had,has,haves），把它反过来用，
  给缺的变形补一条指向原词的条目。

  ⚠ 两个坑：
    1. **重跑 build-data.mjs 会覆盖掉这个补丁**，跑完记得再跑一遍 patch-inflections.mjs
       （脚本是幂等的，跑几次结果一样）
    2. dict.json 的插入顺序**不是**纯词频顺序：前 ~14000 条是
       「只靠考纲标签入选、frq=0」的词，排在前面且基本按字母序。
       真正的词频段从 "the"（第 14166 个）开始。算排名必须减掉这个偏移 ——
       不减的话 have 会被当成 14173 名的生僻词，abnegate 反而成了最高频。
       脚本里 FREQ_OFFSET 就是干这个的。

  补了 13460 条，dict.json 6.4MB -> 8.5MB。只补词频前 12000 名的原词的变形；
  试过把词书词也算进来，要补 25884 条、涨到 10.2MB，买的是 GRE 生僻词的变形，不值。

底部导航栏的液态玻璃
──────────────────────
  · src/glass.ts                   生成位移贴图 + SVG 滤镜，并用行内样式挂上去
  · src/index.css                  搜 "tabbar-glass"

  ⚠ 最大的一个坑：**不要在 CSS 里手写 backdrop-filter。**
  Tailwind v4 走 Lightning CSS 做转换，实测它会把
  `backdrop-filter` 和 `-webkit-backdrop-filter` 两条合并成只留 `-webkit-` 那一条，
  而不带前缀的那条才是当前 Chrome 认的 —— 结果折射完全上不去，
  计算值是 `none`，但你去查 CSSOM 只会看到"这条属性是空的"，很难查。
  所以折射由 glass.ts 用**行内样式**挂（行内样式不过构建管道）。
  CSS 里只留兜底的 `backdrop-filter: blur(14px)`（这条 Lightning CSS 会正确加前缀）。

  ⚠ 网上流传的那份 demo（Shu Ding 的 liquid-glass）不能直接搬：
  它的 `roundedRectSDF(ix, iy, 0.3, 0.2, 0.6)` 是给 **300×200 圆角面板**按归一化坐标算的，
  套到 **390×56 的横条**上距离场形状完全不对，导航栏左侧会糊出一坨灰。
  glass.ts 改成按像素算，只做上下两条边的倒角 —— 横向贯穿屏幕的导航栏
  做四周收边没有意义，左右两端贴在屏幕边上没人看得到。

  兼容性：`backdrop-filter: url()` 只有 Chromium 系支持。
  Safari / Firefox 会**整条声明作废**，所以兜底必须单独写一条规则 ——
  写进同一条的话，它们连 blur 都拿不到，导航栏会变成全透明、字压在内容上。

  实测：位移贴图 390×56 只要 1 KB（base64），生成一次 37ms，不做逐帧重算。
  效果本身是**克制**的 —— 因为 App 背景是纯色平面，没多少东西可折射。
  想让折射更明显，得让内容真的从导航栏底下滚过去。

────────────
  · src/data/onlineDicts.json     372 部词典的目录（名字/分类/文件名），随 App 打包
  · src/onlineDicts.ts            下载 + 解析。源是 qwerty-learner（MIT），走 jsDelivr CDN
  · src/components/OnlineDicts.tsx  浏览/搜索/下载的界面
  · src/components/WordBookTree.tsx 「词书」页那棵梅树
  · src/db.ts                     v5 新增 myBooks 表，词条整本存 IndexedDB

  要重新生成目录的话：原始清单在 qwerty-learner 仓库的
  src/resources/dictionary.ts，解析时要处理两件事（已经处理过，改的时候别丢）：
    1. 同一个文件被两个分类重复列出的（牛津5000）—— 按 file 去重
    2. 两个不同词典共用同一个 id 的（frequently_used_words03）—— 加后缀
  不去重的话 React 的 key 会重复，列表会渲染出幽灵行。

  词条格式：{ name, trans[], usphone?, ukphone?, notation? }
  日语假名那批整本没有 trans，字在 notation 里、罗马音在 name 里，
  所以遇到这种整本对调（字当词、罗马音当释义）。Grep 'const swap'。

  梅枝的几个关键点（改的时候别改坏）：
    STEM / TWIGS      枝条路径。侧枝起点必须落在主干上，否则会像悬空的一根
    RICH_BLOOMS       开场页的 4 朵花；SIMPLE_BLOOMS 是开关那 3 朵（放大过，40px 才看得清）
    BUDS              永远不参与开合的花苞，全开就不像梅花了
    花丝只在 rich 版画 —— 40px 下会糊成一团
    花萼（.plum-calyx）平时是花苞，开花后缩成花心。它的透明度必须比枝干低，
    亮过枝干就变成"铁丝串珠子"了，那是珠子不是花苞

  想调音乐：
    满值是 music.ts 里的 MAX_GAIN（0.2），默认音量 DEFAULT_VOLUME = 50
    调式：同文件的 SCALE 和 ROOT（现在是大调五声音阶 + A3）
    音色：同文件的 PRESETS 数组，加一项就多一种
  状态存在 localStorage 的 scoop.music / scoop.music.volume / scoop.music.preset


已知的坑（都已修复，记在这里免得再踩）
────────────────────────────────────

0. 【最重要】这个项目的深色模式是把 zinc 色阶整体翻转的，
   写在 src/index.css 的 html.dark 里：
       zinc-100 -> #232328（深）      zinc-800 -> #ebebef（浅）
       zinc-400 -> #7c7c86            zinc-700 -> #d8d8de（浅）
   所以【绝对不要写 dark: 变体】。写了就是反的 ——
   我加过 dark:text-zinc-200，深色下反而变成深灰，花在深色底上几乎看不见。
   正确做法：只写浅色意图的类（text-zinc-800），深色会自动翻过来。
   全项目现在一个 dark: 都没有，grep 一下就知道了。

   顺带：深色下的对比度实测是这样，改颜色前后拿这个对一下
       开的花 16.6 : 1 ／ 花苞 7.7 : 1 ／ 枝干 4.8 : 1

1. build-desktop.mjs 原来把输出目录写死成桌面的「英语背单词」。
   文件夹一改名，它就会在桌面另建一个旧名字的文件夹，产物被劈成两半。
   现在改成跟着源码走：输出到「源代码」的上一级目录。

2. build-desktop.mjs 原来复制「源代码」时，如果脚本本身就跑在那个文件夹里，
   会先 rmSync 再 copy = 把源码自己删光。
   现在检测到源和目标同目录会跳过自拷贝。

3. 桌面单文件版的「查单词」原来整个是坏的：
   dict / sentences / cn / zhsent 被当成对象字面量塞进打包脚本，
   new Response(对象) 只会得到字符串 "[object Object]"，res.json() 当场抛错。
   而且异常被 finally 吃掉，界面上什么都不显示，所以很难发现。
   现在返回前会 JSON.stringify 回真正的 JSON 文本。

4. 全局点击涟漪原来用 CSS class 给按钮加 position/overflow，
   但按钮重渲时 React 会把整个 className 写回去，把 class 抹掉，
   涟漪就失去定位参照也没被裁剪。现在改成直接写行内样式。


字体说明
────────
大数字、标题和品牌字用的是系统自带宋体，没有加载任何 webfont：

    Songti SC → Noto Serif CJK SC → Noto Serif SC → Source Han Serif SC
    → Cambria → Georgia → Times New Roman → serif

iOS 用系统宋体，安卓用 Noto Serif，Windows 回落 Noto Serif SC / Cambria。
中文 webfont 动辄好几 MB，为几个字母不值得，PWA 首屏也受不了。
